# sqlplus-session: session handoff — 2026-08-13

## What this is

A general-purpose Python package that maintains a persistent Oracle sqlplus
session over stdin/stdout pipes, eliminating the per-query
connect/authenticate overhead. Stdlib only, Python 3.2.5+. No cx_Oracle, no
python-oracledb, no third-party dependencies.

The first consumer is a client E2E test harness with 24
`run_sql`/`run_sql_file` call sites, each spawning a fresh
csh / environment-bootstrap / sqlplus chain. This package replaces that
chain with a single persistent session.

The package carries no knowledge of that client, its environment
bootstrap, or anything else not already public — and neither does
anything in this repository, handoff notes included. That boundary is
load-bearing. The git history was recreated from scratch to enforce it.
Client-specific detail lives in the private notes tree, not here.

## What was built

### Package (`sqlplus_session/`)

Three files, 11 KB total:

- `session.py` — the core module. `SqlplusSession` class with `query()`,
  `execute()`, `run_file()`, `close()`, and `alive`. Context manager support.
  A daemon reader thread drains stdout into a `Queue`; the main thread
  imposes per-query timeouts via `Queue.get(timeout=)`. Numbered sentinel
  protocol (`PROMPT __EOQ__<n>__`) prevents stale-match cross-talk between
  queries.

- `_errors.py` — exception hierarchy. `SqlplusError` base, then
  `SqlplusConnectError`, `SqlplusOraError` (carries `.errors` and `.output`),
  `SqlplusTimeout` (session is dead after this), `SqlplusDied` (carries
  `.returncode`).

- `__init__.py` — exports all public names, `__version__ = '0.1.0'`.

### Constructor parameters

```python
SqlplusSession(username, password, connect_string,
               sqlplus_cmd='sqlplus', env=None, setup_commands=None,
               connect_timeout=30, default_timeout=60,
               error_patterns=None, on_error='raise',
               path_converter=None)
```

OS authentication works: pass `username=''`, `password=''`, `connect_string='orclpdb1'`
and the login string becomes `/@orclpdb1`.

`on_error='raise'` scans output for ORA-/TNS-/SP2- patterns and raises
`SqlplusOraError`; `on_error='return'` hands the error lines back to the
caller. Custom `error_patterns` replace the defaults entirely.

`path_converter` is for Cygwin — pass a `cygpath -m` wrapper so `run_file()`
converts POSIX paths to the mixed Windows form that Windows sqlplus expects.

### Default setup commands

```
SET PAGESIZE 0 / HEADING OFF / FEEDBACK OFF / VERIFY OFF / ECHO OFF
SET TRIMSPOOL ON / LINESIZE 4000
WHENEVER SQLERROR CONTINUE
```

`WHENEVER SQLERROR CONTINUE` keeps the session alive after ORA errors. The
caller can override with `setup_commands=[]` or their own list.

### Tests (`tests/`)

- `fake_sqlplus.py` — subprocess stand-in for real sqlplus. Responds to
  SELECT with canned output, honors PROMPT (sentinel), ignores SET/WHENEVER.
  Control commands: `__FAKE_DIE__`, `__FAKE_HANG__`, `__FAKE_ORA_ERROR__`,
  `__FAKE_SLOW__<N>__`. Mode 755.

- `test_session.py` — **40 unit tests**, all pass. No database required.
  Covers: construction, query, execute, run_file, error handling (raise +
  return modes), custom error patterns, timeouts, process death, lifecycle,
  `_terminate_sql`, sentinel counter, exception hierarchy, setup commands.

- `test_spike_oracle.py` — **6 integration tests**, all pass on real Oracle.
  Requires live sqlplus + database. Covers: persistent session timing,
  per-call baseline comparison, error scanning, on_error=return,
  multi-statement, lifecycle. Mode 755.

## The bug that was found and fixed

The original spike timed out during the constructor's probe query. Root cause:
`_raw_query()` wrote `sql_text` without ensuring a trailing newline. The
constructor called `_raw_query('SELECT 1 FROM DUAL;', timeout=30)` — no `\n`
at the end. sqlplus saw `SELECT 1 FROM DUAL;PROMPT __EOQ__1__` as one line
instead of two separate commands.

The `query()` path worked because `_terminate_sql()` adds `\n`.

Fix: `_raw_query()` now always ensures a trailing newline:

    if not sql_text.endswith('\n'):
        sql_text += '\n'

The `terminate` parameter was removed entirely.

Three probe scripts (`pipe_probe.py`, `pipe_probe2.py`, `pipe_probe3.py`)
confirmed the pipe and sentinel protocol work correctly on Cygwin before the
bug was isolated.

## Python 3.2.5 compatibility

The module uses these patterns to stay compatible:

- `%`-formatting, never f-strings
- `try: import queue / except ImportError: import Queue as queue`
- `open(os.devnull, 'w')` instead of `subprocess.DEVNULL` (3.3+)
- `universal_newlines=True` instead of `text=True` (3.7+)
- `t.daemon = True` as attribute, not `Thread(daemon=True)` kwarg (3.3+)
- `iter(pipe.readline, '')` instead of `for line in pipe` (avoids
  read-ahead buffer deadlock at 3.2)
- `Queue.get(timeout=)` for timeouts instead of `selectors` (3.4+)
- `super(ClassName, self).__init__(...)` instead of bare `super()` (3.3+)
- `class Foo(object):` instead of bare `class Foo:` for explicit new-style
- `Popen.communicate(timeout=)` is 3.3+; the env-file bootstrap in
  `test_spike_oracle.py` catches `TypeError` and falls back to no-timeout

Not yet verified with an actual 3.2 interpreter. The RHEL replica has 3.6.9,
which is closer but still not 3.2. A `py_compile` pass on 3.2 is owed.

## Key design decisions

- **Sentinel protocol, not EOF.** Each query is followed by
  `PROMPT __EOQ__<n>__`. The reader collects lines until the sentinel
  appears. The counter prevents a stale sentinel from a timed-out query
  from being mistaken for the current one.

- **Reader thread + Queue.** `selectors` is 3.4+; `Queue.get(timeout=)` is
  available at 3.2. The thread runs `iter(pipe.readline, '')` which calls
  `readline()` one line at a time — `for line in pipe` uses Python's
  read-ahead buffer and can deadlock.

- **Timeout kills the process.** A timed-out query means the session is
  wedged. The process is killed, `self._closed = True`, and
  `SqlplusTimeout` is raised. The caller must open a new session.

- **ORA errors do not kill the session.** `WHENEVER SQLERROR CONTINUE`
  keeps sqlplus alive. The error is detected by regex scan of the output
  and either raised or returned per the `on_error` policy.

- **os.execv wrapper on Cygwin.** The `/usr/local/bin/sqlplus` wrapper on
  ins-15 uses `os.execv` to replace itself with the real Windows
  sqlplus.exe, converting POSIX path arguments via `cygpath -m`. It is not
  an extra process layer — confirmed by the probe scripts and the timing
  numbers.
